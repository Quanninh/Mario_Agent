## 2. Artifact 1: Q-Table Checkpoints (`.json` & `.pkl`)

### 2.1 File Structure & Wrapper Metadata
Every `.json` checkpoint serialized by `TabularQAgent.save()` conforms to the following schema:

```json
{
  "num_states_discovered": 384,
  "num_actions": 5,
  "alpha": 0.1,
  "gamma": 0.99,
  "epsilon": 0.01,
  "epsilon_min": 0.01,
  "epsilon_decay": 0.995,
  "q_table": {
    "1,0,2,1,0,0,0": [0.0, -1.2, 4.5, 12.8, 48.2],
    "1,-1,0,0,2,0,0": [1.5, 0.0, 32.1, 8.4, 25.0]
  }
}
```

### 2.2 The 864-State 7-Tuple State Representation
The Q-table keys are comma-separated string encodings of the discrete 7-tuple:
$$\mathcal{S} = \langle \text{is\_grounded}, \; V_{y\text{-sign}}, \; \text{Obstacle}_{\text{dist}}, \; \text{Obstacle}_{\text{height}}, \; \text{Pit}_{\text{dist}}, \; \text{Ghost}_{\text{dist}}, \; \text{Ghost}_{\text{alt}} \rangle$$

$$\text{Total State Cardinality} = 2 \times 3 \times 4 \times 2 \times 3 \times 3 \times 2 = 864 \text{ states}$$

| Dimension | Meaning | Cardinality | Bins & Exact Mathematical Boundaries |
| :--- | :--- | :---: | :--- |
| `is_grounded` | Floor contact | 2 | `0`: Airborne, `1`: Resting on solid ground or obstacle top |
| `vy_sign` | Vertical velocity | 3 | `1`: Ascending ($v_y < -0.1$ px/tick)<br>`0`: Flat/stationary ($-0.1 \le v_y \le 0.1$ px/tick)<br>`-1`: Falling ($v_y > 0.1$ px/tick) |
| `obstacle_dist` | Tombstone ahead | 4 | `0`: NONE ($d < 0$, $d > 80$ px, or vertically cleared: $\text{feet} \le 320 - h + 2$ px)<br>`1`: FAR ($40 \le d \le 80$ px)<br>`2`: CLOSE ($15 \le d < 40$ px)<br>`3`: IMMEDIATE ($0 \le d < 15$ px) |
| `obstacle_height`| Tombstone height | 2 | `0`: LOW / NONE ($h \le 50.0$ px or cleared)<br>`1`: HIGH ($h > 50.0$ px; calibrated for $56\text{--}68$ px obstacles) |
| `pit_dist` | Grave pit ahead | 3 | `0`: NONE ($d < 0$ or $d > 80$ px)<br>`1`: FAR ($32 < d \le 80$ px, approach corridor)<br>`2`: IMMEDIATE ($0 \le d \le 32$ px, take-off window) |
| `ghost_dist` | Ghost proximity | 3 | `0`: NONE ($d < 0$, $d > 80$ px, or vertically cleared above: $\text{feet} \le y_{\text{ghost}}$)<br>`1`: FAR ($35 < d \le 80$ px)<br>`2`: CLOSE ($0 \le d \le 35$ px, avoidance corridor) |
| `ghost_alt` | Ghost altitude | 2 | `0`: LOW / NONE ($y_{\text{ghost}} \ge 260$ px $\to$ jump over)<br>`1`: HIGH ($y_{\text{ghost}} < 260$ px $\to$ walk under while grounded) |

### 2.3 Action Values (5-Float Array)
Each state maps to a float array of length 5 corresponding to `core.Action`:
- `Index 0`: `STAY`
- `Index 1`: `LEFT`
- `Index 2`: `JUMP`
- `Index 3`: `RIGHT`
- `Index 4`: `RIGHT_JUMP`

### 2.5 Best Checkpointing (3-Tuple Ranking & Stage Backups)
- **Curriculum Global Best (`q_table_best.{json,pkl}`)**:
  Ranked strictly via the **3-tuple**:
  $$\text{Score} = (\text{num\_unlocked\_levels}, \; \overline{\text{win\_rate}}, \; \overline{\text{avg\_reward}})$$
  Where evaluation is conducted greedily across all unlocked levels up to the current stage ($\text{levels}[:\text{lvl\_idx} + 1]$). Higher level counts strictly dominate earlier stages, ensuring the global best model always represents the most capable multi-level policy rather than getting frozen on early levels.
- **Per-Stage Best Backups (`q_table_lvl{N}_best.{json,pkl}`)**:
  Saved whenever the greedy evaluation score $(\text{win\_rate}, \text{avg\_reward})$ reaches a new high during or at completion of that specific level stage.
- **Default Hyperparameters**:
  - `episodes_per_level`: `2000` (server production default)
  - `epsilon_decay`: `0.997`
  - `checkpoint_interval`: `400` episodes

### 3.3 `episode_history` Section
A list of 14-field dictionary objects recording every single training episode:

```json
{
  "global_episode": 205,
  "level_episode": 5,
  "level_id": 2,
  "total_reward": 1240.5,
  "steps": 268,
  "max_x_reached": 1100.0,
  "progress_pct": 100.0,
  "obstacle_hits": 0,
  "items_collected": 0,
  "items_total": 0,
  "epsilon": 0.285,
  "won": true,
  "outcome": "win",
  "rolling_win_rate_50": 88.0
}
```

#### Field Formulas & Valid Values
1. `global_episode`: Monotonically increasing 1-based episode index across the entire run ($1 \dots N_{\text{levels}} \times E_{\text{level}}$).
2. `level_episode`: 1-based episode index within current level ($1 \dots E_{\text{level}}$).
3. `level_id`: Active level ID ($1 \dots 5$).
4. `total_reward`: Sum of all tick rewards in this episode ($\sum r_{t+1}$).
5. `steps`: Total physics ticks elapsed before termination ($1 \dots \text{max\_steps}$).
6. `max_x_reached`: Furthest horizontal coordinate attained ($\max_{t} x_t$).
7. `progress_pct`: Horizontal progress normalized against total level span, taking into account player hitbox width (`24.0px`):
   $$\text{effective\_goal\_x} = \max(x_{\text{start}} + 1.0, \; x_{\text{goal}} - \text{player\_width})$$
   $$\text{progress\_pct} = \begin{cases} 100.0, & \text{if } \text{won} \\ \min\left(100.0, \; \max\left(0.0, \; \frac{\max x - x_{\text{start}}}{\text{effective\_goal\_x} - x_{\text{start}}} \times 100\right)\right), & \text{otherwise} \end{cases}$$
   Every winning episode strictly records `progress_pct == 100.0`.
8. `obstacle_hits`: Count of tombstone lateral side collisions.
9. `items_collected`: Warmth collectibles gathered in this episode.
10. `items_total`: Total collectibles placed in this level ($0$ on L1–2, $3$ on L3–4, $4$ on L5).
11. `epsilon`: Current exploration rate after episode decay (rounded to 6 decimal places).
12. `won`: Boolean (`True` if `reached_goal`, `False` otherwise).
13. `outcome`: Discrete terminal status string, exactly one of:
    - `"win"`: Player reached Hoá's home.
    - `"ghost_death"`: Player touched a patrolling ghost.
    - `"pit_death"`: Player fell below screen bottom in an open grave pit.
    - `"timeout"`: Player exceeded `max_steps` without reaching the goal or dying.
14. `rolling_win_rate_50`: Trailing win percentage over the last 50 episodes within the current level (reset per level so Episode 1 of a new level starts at 0.0% / fresh window).

## 5. Visual Demo & Replay Usage for Member 4

To inspect trained agents or present live 60 FPS visual demonstrations:

```bash
# Launch default canonical best policy on Level 1
python play_agent.py

# Launch Level 4 with trained balanced agent
python play_agent.py --level 4 --reward balanced --variant best

# Interactive Hotkeys in playback window:
# [1..5]  : Switch level live
# [F1..F3]: Live-swap reward strategy (Balanced, Sparse, Dense)
# [T]     : Toggle between Best and Final checkpoint
# [Space] : Pause / Resume
# [R]     : Restart episode
# [Esc]   : Exit
```
